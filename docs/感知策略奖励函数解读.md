## 0. 先看懂三件事

### 0.1 奖励怎么加总

InstinctLab 的 `RewardManager`（`InstinctLab/.../managers/reward_manager.py:144`）对每一项计算：

```
每步奖励 += 函数值 × 权重 × dt          （dt = 0.02 s，即 50 Hz 控制频率）
```

所以一个回合（20 s，1000 步）里，某项的累计值 = Σ(函数值 × 权重 × 0.02)。下文表格里的“每回合”都是这个口径。AMP 风格奖励**不乘 dt**，在 PPO 里直接加到每一步的奖励上（见第 8 节）。

### 0.2 速度指令从哪来：走向目标点

`env_cfg:624` 的 `CommandsCfg`：

```python
base_velocity = mdp.PoseVelocityCommandCfg(
    asset_name="robot",
    resampling_time_range=(8.0, 12.0),
    velocity_control_stiffness=2.0,
    heading_control_stiffness=2.0,
    rel_standing_envs=0.05,
    ...
    velocity_ranges={
        "perlin_rough": {"lin_vel_x": (0.45, 1.0), "lin_vel_y": (0.0, 0.0), "ang_vel_z": (-1.0, 1.0)},
        "perlin_rough_stand": {"lin_vel_x": (0.0, 0.0), "lin_vel_y": (0.0, 0.0), "ang_vel_z": (0.0, 0.0)},
        "square_gaps": {"lin_vel_x": (0.45, 0.8), ...},   # 其余地形都是 0.45–0.8
        ...
    },
    only_positive_lin_vel_x=True,
    target_dis_threshold=0.4,
)
```

`mdp/commands/pose_velocity_command.py:227` 中的 `_update_command` 每一步都会重新计算：

```python
target_vec = self.pos_command_w - self.robot.data.root_pos_w[:, :3]
target_dist = torch.norm(target_vec[:, :2], dim=1)
self.pos_command_b[:] = quat_rotate_inverse(yaw_quat(self.robot.data.root_quat_w), target_vec)
self.vel_command_b[:, :2] = self.pos_command_b[:, :2] * self.cfg.velocity_control_stiffness   # 2.0 × 距离
...
self.heading_command_w = wrap_to_pi(target_direction - self.robot.data.heading_w)
self.vel_command_b[:, 2] = self.heading_command_w * self.cfg.heading_control_stiffness          # 2.0 × 朝向误差
...  # 按地形裁剪到上面的速度范围
self.vel_command_b[:] *= (target_dist > self.cfg.target_dis_threshold).unsqueeze(-1)            # 到达 0.4 m 内 → 指令清零
```

- 每 8–12 s 在地块的平坦区域里随机选一个目标点；
- 前向速度 = 2 × 距离，裁剪到 0.45–0.8 m/s（起伏地形是 0.45–1.0）；
- 转向角速度 = 2 × 朝向误差，裁剪到 ±1 rad/s；
- **离目标不到 0.4 m 时三个分量全部清零**，等价于要求原地站住；
- 5% 的机器人在 `perlin_rough_stand` 地块上，一直收到零指令。

后面所有“跟踪速度”的奖励，本质上都是在奖励**朝目标走过去，到了就站住**。

### 0.3 观测里没有、奖励里有的信息

策略只看本体感知和 8 帧深度图（64×36）。但奖励用到了几个**特权传感器**：腿上的虚拟体积点（`leg_volume_points`）、左右脚底的高度扫描（`left/right_height_scanner`），以及全身的接触力。这是标准的非对称设计：奖励可以用仿真里的真值，策略不行。

## 2. 任务奖励

### 2.1 `is_alive`　权重 +3.0

配置（`env_cfg:674`）：
```python
is_alive = RewTerm(func=mdp.is_alive, weight=3.0)
```
函数（`isaac_rew:31`）：
```python
def is_alive(env: ManagerBasedRLEnv) -> torch.Tensor:
    """Reward for being alive."""
    return (~env.termination_manager.terminated).float()
```
- **公式**：没有被终止就是 1，否则是 0。每步 3.0 × 0.02 = 0.06，满长回合最多 +60。
- **作用**：最主要的正奖励，结束时约占任务奖励的一半（58.5 / 112.2）。它让“摔倒”的代价变成“失去后面所有的存活奖励”。

### 2.2 `track_lin_vel_xy_exp`　权重 +2.0

配置（`env_cfg:664`）：
```python
track_lin_vel_xy_exp = RewTerm(
    func=mdp.track_lin_vel_xy_exp,
    weight=2.0,
    params={"command_name": "base_velocity", "std": 0.5},
)
```
函数（`isaac_rew:287`）：
```python
def track_lin_vel_xy_exp(
    env: ManagerBasedRLEnv, std: float, command_name: str, asset_cfg: SceneEntityCfg = SceneEntityCfg("robot")
) -> torch.Tensor:
    """Reward tracking of linear velocity commands (xy axes) using exponential kernel."""
    asset: RigidObject = env.scene[asset_cfg.name]
    lin_vel_error = torch.sum(
        torch.square(env.command_manager.get_command(command_name)[:, :2] - asset.data.root_lin_vel_b[:, :2]),
        dim=1,
    )
    return torch.exp(-lin_vel_error / std**2)
```
- **公式**：exp(−‖v_cmd,xy − v_xy‖² / 0.25)，值域 (0, 1]。速度误差为 0.25 m/s 时约 0.78，0.5 m/s 时约 0.37。
- **作用**：主要的任务奖励。注意 `root_lin_vel_b` 是躯干的速度（这个机器人的根节点是躯干）。

def track_ang_vel_z_exp(
    env: ManagerBasedRLEnv, std: float, command_name: str, asset_cfg: SceneEntityCfg = SceneEntityCfg("robot")
) -> torch.Tensor:

### 2.4 `stand_still`　权重 −0.3（实际上多半是**正奖励**）

配置（`env_cfg:675`）：
```python
stand_still = RewTerm(func=mdp.stand_still, weight=-0.3, params={"command_name": "base_velocity", "offset": 4.0})
```
函数（`parkour_rew:38`）：
```python
def stand_still(
    env: ManagerBasedRLEnv,
    command_name: str,
    asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
    threshold: float = 0.15,
    offset: float = 1.0,
) -> torch.Tensor:
    """Penalize moving when there is no velocity command."""
    asset = env.scene[asset_cfg.name]
    dof_error = torch.sum(torch.abs(asset.data.joint_pos - asset.data.default_joint_pos), dim=1)
    return (
        (dof_error - offset)
        * (torch.norm(env.command_manager.get_command(command_name)[:, :2], dim=1) < threshold)
        * (torch.abs(env.command_manager.get_command(command_name)[:, 2]) < threshold)
    )
```
- **公式**：只在指令接近零时生效（线速度 < 0.15 且角速度 < 0.15），值 = (Σ|q − q_default| − 4.0)。
- **为什么实际是奖励**：减去 `offset=4.0` 之后，只要 29 个关节偏离默认姿态的总和小于 4 rad，函数值就是负数，乘上负权重就成了**正奖励**。姿态越接近默认站姿，奖励越大；只有偏离超过 4 rad 才是惩罚。
- **什么时候生效**：不只对 5% 的站立机器人生效。**任何机器人走到目标 0.4 m 以内，指令被清零后也会生效**（见 0.2 节）。所以它实际在奖励“到了目标就站好、回到默认姿态”。
- **训练数据**：从 +0.2 涨到 +7.9，说明后期大量机器人能及时走到目标并站稳。

### 2.5 `heading_error`　权重 −1.0

配置（`env_cfg:672`）：
```python
heading_error = RewTerm(func=mdp.heading_error, weight=-1.0, params={"command_name": "base_velocity"})
```
函数（`parkour_rew:94`）：
```python
def heading_error(env: ManagerBasedRLEnv, command_name: str) -> torch.Tensor:
    """Compute the heading error between the robot's current heading and the goal heading."""
    ang_vel_cmd = torch.abs(env.command_manager.get_command(command_name)[:, 2])
    return ang_vel_cmd
```
- **公式**：|ω_cmd,z|。转向指令 = 2 × 朝向误差（裁剪到 ±1），所以这一项罚的就是**没对准目标的程度**。
- **作用**：配合 `track_ang_vel_z_exp`，让机器人尽快转向目标并一直对准目标走。它罚的是指令而不是动作，策略只能靠真正转过去来消除它。

### 2.6 `dont_wait`　权重 −0.5

配置（`env_cfg:673`）：
```python
dont_wait = RewTerm(func=mdp.dont_wait, weight=-0.5, params={"command_name": "base_velocity"})
```
函数（`parkour_rew:101`）：
```python
def dont_wait(
    env: ManagerBasedRLEnv, command_name: str, asset_cfg: SceneEntityCfg = SceneEntityCfg("robot")
) -> torch.Tensor:
    """Penalize standing still when there is a forward velocity command."""
    asset: RigidObject = env.scene[asset_cfg.name]
    lin_vel_cmd_x = env.command_manager.get_command(command_name)[:, 0]
    lin_vel_x = asset.data.root_lin_vel_b[:, 0]
    return (lin_vel_cmd_x > 0.3) * ((lin_vel_x < 0.15).float() + (lin_vel_x < 0).float() + (lin_vel_x < -0.15).float())
```
- **公式**：前向指令 > 0.3 时，实际前向速度 < 0.15 罚 1，< 0 再罚 1，< −0.15 再罚 1（最多 3）。
- **作用**：防止在障碍物前“原地踏步”拖时间、混存活奖励。第 3000 次迭代时最大（−4.2），这时课程学习正把机器人推向难地形，它们会在障碍前犹豫；结束时降到 −0.5。

### 3.1 `volume_points_penetration`　权重 −4.0

配置（`env_cfg:678`）：
```python
volume_points_penetration = RewTerm(

    params={
        "sensor_cfg": SceneEntityCfg("leg_volume_points"),

```
穿鞋版会改这个传感器的采样范围（`g1_cfg:98`）：
```python
self.scene.leg_volume_points.points_generator.z_min = -0.063
self.scene.leg_volume_points.points_generator.z_max = -0.023
```
函数（`instinct_vp:15`）：
```python
def volume_points_penetration(
    env: ManagerBasedRLEnv, sensor_cfg: SceneEntityCfg, tolerance: float = 0.0
) -> torch.Tensor:
    """Penalize the penetration of volume points into the environment."""
    volume_sensor: VolumePoints = env.scene.sensors[sensor_cfg.name]
    penetration = volume_sensor.data.penetration_offset  # (N, B_, P_, 3)
    penetration = penetration.flatten(1, 2)  # (N, B_*P_, 3)
    penetration_depth = torch.norm(penetration, dim=-1)  # (N, B_*P_)
    in_obstacle = (penetration_depth > tolerance).float()  # (N, B_*P_)
    points_vel = volume_sensor.data.points_vel_w  # (N, B_, P_, 3)
    points_vel = points_vel.flatten(1, 2)  # (N, B_*P_, 3)
    points_vel_norm = torch.norm(points_vel, dim=-1)  # (N, B_*P_)
    velocity_times_penetration = in_obstacle * (points_vel_norm + 1e-6) * penetration_depth  # (N, B_*P_)
    return torch.sum(velocity_times_penetration, dim=-1)
```
- **公式**：在腿部连杆里采样一组点，对每个嵌进地形 / 障碍物（虚拟障碍物）的点，罚 **穿透深度 × 该点的速度**，再对所有点求和。
- **作用**：**这是唯一真正和地形几何有关的奖励**。它惩罚的是“带着速度撞进 / 刮过障碍物”，比如踢到台阶边缘、腿擦着箱子过去。乘上速度，是为了不惩罚静止时的轻微接触。
- **训练数据**：开始 −0.9，第 3000 次迭代 −3.9（课程学习在推难度），结束 −0.8。说明它后来学会了抬腿越过障碍。

函数（`isaac_rew:260`）：
```python
def undesired_contacts(env: ManagerBasedRLEnv, threshold: float, sensor_cfg: SceneEntityCfg) -> torch.Tensor:
    """Penalize undesired contacts as the number of violations that are above a threshold."""
    contact_sensor: ContactSensor = env.scene.sensors[sensor_cfg.name]
    net_contact_forces = contact_sensor.data.net_forces_w_history
    is_contact = torch.max(torch.norm(net_contact_forces[:, :, sensor_cfg.body_ids], dim=-1), dim=1)[0] > threshold

```

- **作用**：不许用膝盖、手、小腿去碰地形。注意躯干（`torso_link`）碰到东西会直接终止回合（见第 9 节），比这一项严重得多。

def feet_air_time(env, command_name: str, vel_threshold: float, sensor_cfg: SceneEntityCfg) -> torch.Tensor:
    contact_sensor: ContactSensor = env.scene.sensors[sensor_cfg.name]
    air_time = contact_sensor.data.current_air_time[:, sensor_cfg.body_ids]
    contact_time = contact_sensor.data.current_contact_time[:, sensor_cfg.body_ids]
    in_contact = contact_time > 0.0
    in_mode_time = torch.where(in_contact, contact_time, air_time)
    single_stance = torch.sum(in_contact.int(), dim=1) == 1
    reward = torch.min(torch.where(single_stance.unsqueeze(-1), in_mode_time, 0.0), dim=1)[0]
    # no reward for zero command
    reward *= torch.logical_or(
        torch.norm(env.command_manager.get_command(command_name)[:, :2], dim=1) > vel_threshold,
        torch.abs(env.command_manager.get_command(command_name)[:, 2]) > vel_threshold,
    )
    return reward

    env: ManagerBasedRLEnv,

```python
def feet_close_xy_gauss(
    env: ManagerBasedRLEnv, threshold: float, asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"), std: float = 0.1
) -> torch.Tensor:
    """Penalize when feet are too close together in the y distance."""
    asset = env.scene[asset_cfg.name]
    left_foot_xy = asset.data.body_pos_w[:, asset_cfg.body_ids[0], :2]
    right_foot_xy = asset.data.body_pos_w[:, asset_cfg.body_ids[1], :2]
    heading_w = asset.data.heading_w
    cos_heading = torch.cos(heading_w)
    sin_heading = torch.sin(heading_w)
    left_foot_robot_frame = torch.stack(
        [
            cos_heading * left_foot_xy[:, 0] + sin_heading * left_foot_xy[:, 1],
            -sin_heading * left_foot_xy[:, 0] + cos_heading * left_foot_xy[:, 1],
        ],
        dim=1,
    )
    right_foot_robot_frame = torch.stack(
        [
            cos_heading * right_foot_xy[:, 0] + sin_heading * right_foot_xy[:, 1],
            -sin_heading * right_foot_xy[:, 0] + cos_heading * right_foot_xy[:, 1],
        ],
        dim=1,
    )
    feet_distance_y = torch.abs(left_foot_robot_frame[:, 1] - right_foot_robot_frame[:, 1])
    return torch.exp(-torch.clamp(threshold - feet_distance_y, min=0.0) / std**2) - 1
```
- **公式**：把两脚位置转到机器人朝向坐标系，算横向距离 d_y。d_y ≥ 0.12 m 时值为 0；小于 0.12 m 时值 = exp(−(0.12 − d_y) / 0.05) − 1，在 (−1, 0) 之间。
- **作用**：权重是正的，但函数值永远 ≤ 0，所以实际上是**惩罚两脚横向靠得太近**，防止两腿交叉、互相绊脚。结束时 −0.12，比开始时大，可能是在窄的地形（比如缺口）上会收窄步宽。

    )
    # clip to max error = 1 rad/s per joint to avoid huge penalties
    out_of_limits = out_of_limits.clip_(min=0.0, max=1.0)
    return torch.sum(out_of_limits, dim=1)
```
- **公式**：|关节速度| 超过 90% 速度限位的部分，每个关节最多计 1 rad/s，再求和。
- **作用**：不许关节转得太快。

### 7.3 `torque_limits`　权重 −0.01

配置（`env_cfg:786`）：

torque_limits = RewTerm(
    func=mdp.applied_torque_limits_by_ratio,
    weight=-0.01,
    params={
        "asset_cfg": SceneEntityCfg("robot", joint_names=[".*"]),

```
函数（`instinct_reg:760`）：
```python
def applied_torque_limits_by_ratio(
    env: ManagerBasedRLEnv,
    asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
    limit_ratio: float = 0.8,
):
    """Penalize when the applied torque excceed certain ratio of the joint torque limit."""
    asset: Articulation = env.scene[asset_cfg.name]
    joint_effort_limits = asset.data.joint_effort_limits  # (num_envs, num_joints)
    joint_effort_limits = joint_effort_limits[:, asset_cfg.joint_ids]
    applied_torque = asset.data.applied_torque[:, asset_cfg.joint_ids]
    applied_torque = torch.abs(applied_torque)
    out_of_limits = (applied_torque - joint_effort_limits * limit_ratio).clip(min=0)
    out_of_limits_err = torch.sum(torch.square(out_of_limits), dim=-1)  # (num_envs,)
    return out_of_limits_err
```
- **公式**：|力矩| 超过 80% 力矩上限的部分，平方后求和（单位 N²m²）。
- **作用**：给电机留 20% 余量，避免长期顶着上限工作。结束时 −0.31。注意髋俯仰的上限只有 88 Nm，上台阶、上箱子时最容易触发。

## 8. AMP 风格奖励（判别器）

配置（`agent_cfg:43`）：
```python

    }
    discriminator_reward_coef = 0.25
    discriminator_reward_type = "quad"
    discriminator_loss_func = "MSELoss"
    discriminator_gradient_penalty_coef = 5.0
    ...
```
奖励计算（`wasabi:112`）：
```python
@torch.no_grad()
def compute_auxiliary_reward(self, obs_pack: dict[str, torch.Tensor]) -> dict[str, torch.Tensor]:
    super_auxilary_reward = super().compute_auxiliary_reward(obs_pack)
    actor_state = obs_pack[self.actor_state_key]
    disc = self.discriminator(actor_state).detach()
    if self.discriminator_reward_type == "log":
        reward = -torch.log(1 - torch.clamp(torch.sigmoid(disc), 1e-6, 1 - 1e-6))
    elif self.discriminator_reward_type == "quad":
        reward = torch.clamp(1 - (1 / 4) * torch.square(disc - 1), min=0)
    elif self.discriminator_reward_type == "wasserstein":
        reward = disc
    super_auxilary_reward["discriminator_reward"] = reward
    return super_auxilary_reward
```
加到 PPO 的奖励里（`instinct_rl/instinct_rl/algorithms/ppo.py:151`）：
```python
def process_env_step(self, rewards, dones, infos, next_obs, next_critic_obs):
    self.transition.rewards = rewards.clone()
    auxiliary_rewards = self.compute_auxiliary_reward(infos["observations"])
    for k, v in auxiliary_rewards.items():
        coef = getattr(self, f"{k}_coef", 1.0)       # discriminator_reward_coef = 0.25
        if coef != 0.0:
            self.transition.rewards += coef * v * self.auxiliary_reward_per_env_reward_coefs   # 后者默认是 1.0
        infos["step"][k] = v
```
- **判别器的输入**（`env_cfg:512` 的 `AmpPolicyStateObsCfg`，和参考动作那一组 `AmpReferenceStateObsCfg` 一一对应）：重力方向、关节角、关节速度、根线速度、根角速度。
- **参考动作数据**：`parkour_motion_reference` 中的走路数据（`g1_cfg:30`，过滤文件是 `parkour_motion_without_run.yaml`，也就是**去掉了跑步**）。
- **公式**：每步奖励 = 0.25 × clamp(1 − ¼(D − 1)², 0)，其中 D 是判别器的输出。判别器用 MSE 损失训练：参考动作的目标是 +1，策略动作的目标是 −1。所以 D 越接近 1（越像参考动作），奖励越高，最大 0.25。
- **不乘 dt**：AMP 奖励直接加到每步奖励上，而任务奖励每项都乘了 0.02。
- **训练数据**（`Step/discriminator_reward` 记录的是乘 0.25 之前的值）：

| | 开始 | 第 3000 次 | 结束 |
|---|---|---|---|
| 判别器奖励（乘系数前） | 0.35 | 0.49 | 0.62 |
| 每步 AMP 奖励（× 0.25） | 0.088 | 0.122 | **0.155** |
| 每步任务奖励 | 0.042 | 0.064 | **0.110** |
| 判别器对策略动作的输出 | −0.60 | −0.43 | −0.23 |
| 判别器对参考动作的输出 | +0.61 | +0.43 | +0.23 |

结束时判别器对两类输入的输出只差 0.47，越来越难区分策略动作和参考动作，说明动作已经很像人的走路。

函数（`InstinctLab/.../tasks/parkour/mdp/curriculums.py:15`）：
```python
def tracking_exp_vel(env, env_ids, asset_cfg=SceneEntityCfg("robot"),
                     lin_vel_threshold=(0.3, 0.6), ang_vel_threshold=(0.3, 0.5)):
    command = env.command_manager.get_term("base_velocity")
    tracking_exp_vel_xy = command.metrics["tracking_exp_vel_xy"][env_ids]
    tracking_exp_vel_yaw = command.metrics["tracking_exp_vel_yaw"][env_ids]
    move_up = (tracking_exp_vel_xy > lin_vel_threshold[1]) * (tracking_exp_vel_yaw > ang_vel_threshold[1])
    move_down = tracking_exp_vel_xy < lin_vel_threshold[0]
    move_down *= ~move_up
    terrain.update_env_origins(env_ids, move_up, move_down)
    return torch.mean(terrain.terrain_levels.float())
```
- 回合结束时，线速度跟踪得分 > 0.6 就升一级，< 0.3 就降一级。
- **角速度的阈值设成了 0**，只要得分 > 0 就算达标，等于不看转向。
- 课程只看“走得动不动”，不直接看“摔没摔”。不过摔了回合就提前结束，得分自然会低。
- 训练数据：平均等级 0.21 → 1.70（第 3000 次）→ 6.06（结束）；线速度得分 0.17 → 0.39 → 0.85。

## 11. 要点总结

1. **奖励的主体是“活着 + 跟着指令走 + 动作像人”**。结束时任务奖励约 112、AMP 约 155 每回合；所有正则项合计只有 −13。
2. **AMP 风格奖励比全部任务奖励加起来还大**（每步 0.155 对 0.110）。因为它不乘 dt，系数 0.25 实际上相当于任务奖励里一个权重 12.5 的项。动作像人主要靠它，但也意味着动作风格对策略的牵制很强。
3. **`stand_still` 的符号容易误读**。权重是负的，但因为 offset = 4.0，它几乎总是正奖励，奖励的是“到达目标后回到默认站姿”。
4. **`heading_error` 罚的是转向指令本身**，等价于要求一直对准目标走。
5. **和地形直接相关的奖励只有 `volume_points_penetration` 和 `undesired_contacts`**，加上 `feet_at_plane` 和 `feet_flat_ori` 管落脚质量。没有针对台阶、箱子、坡道的专门奖励，过地形的能力主要靠课程学习逼出来。这可能是 Small Box、Ramp 掉分最多的原因之一：这两类最容易“擦着障碍物走但不摔”，而穿透惩罚结束时只有 −0.8。
6. **课程只看线速度跟踪**（角速度阈值是 0）。
7. **策略看不到的信息只在奖励里用**：腿部体积点、脚底高度扫描、接触力。策略本身只看本体感知和 8 帧深度图。
8. **对 SONIC 学生实验的影响**：第 1–2 阶段的 DAgger 用不到这些奖励。如果到第 3 阶段要做 PPO 微调，不能原样照搬：AMP 判别器只认走路，会惩罚 SONIC 的跳舞、下蹲；`freeze_upper_body`、`joint_deviation_hip`、`stand_still` 也和全身动作跟踪冲突。这和第零阶段发现的“终止条件只为走路设计”是同一类问题。
